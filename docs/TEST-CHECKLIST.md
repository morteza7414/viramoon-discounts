# چک‌لیست تست دستی — افزونه تخفیف محصولات ویرامون

محیط پیشنهادی: WordPress 6.2+، WooCommerce 7.0+، PHP 7.4/8.1/8.2،
منطقه زمانی `Asia/Tehran`، واحد پول تومان با ۰ رقم اعشار و یک محیط با ۲ رقم اعشار.

## آماده‌سازی

- [ ] بکاپ دیتابیس گرفته شده است.
- [ ] افزونه روی staging فعال است.
- [ ] یک محصول ساده با قیمت اصلی ۱٬۰۰۰٬۰۰۰ ساخته شده است.
- [ ] یک محصول متغیر با ۳ Variation (یکی بدون قیمت اصلی، یکی غیرفعال) ساخته شده است.
- [ ] یک درگاه تست (مثلاً پرداخت نقدی) برای بررسی کارمزد تنظیم شده است.

## ۱) محصول ساده — تخفیف درصدی

- [ ] تب «تخفیف ویرامون» فقط برای محصول ساده دیده می‌شود.
- [ ] تخفیف ۲۰٪ با مقدار ۲۰ ذخیره می‌شود و قیمت نهایی ۸۰۰٬۰۰۰ نمایش داده می‌شود.
- [ ] پیش‌نمایش با تغییر مقدار بلافاصله به‌روز می‌شود.
- [ ] در فروشگاه قیمت حراج ۸۰۰٬۰۰۰ و نشان حراج نمایش داده می‌شود.
- [ ] مقدار ۰، منفی، متن و ۱۰۱ رد می‌شوند و پیام خطا نمایش داده می‌شود.
- [ ] با غیرفعال بودن «تخفیف ۱۰۰٪»، مقدار ۱۰۰ رد می‌شود.
- [ ] با فعال بودن «تخفیف ۱۰۰٪»، مقدار ۱۰۰ پذیرفته و قیمت صفر می‌شود.

## ۲) محصول ساده — مبلغ ثابت

- [ ] تخفیف ۱۵۰٬۰۰۰ روی قیمت ۱٬۰۰۰٬۰۰۰ قیمت نهایی ۸۵۰٬۰۰۰ می‌دهد.
- [ ] مبلغ بیشتر از قیمت اصلی (با غیرفعال بودن اجازه ۱۰۰٪) رد می‌شود.
- [ ] با فعال بودن اجازه ۱۰۰٪، مبلغ بیشتر از قیمت، قیمت نهایی صفر می‌دهد (نه منفی).

## ۳) گرد کردن

- [ ] روش «عدد صحیح» قیمت ۸۵۰٬۵۰۰ را به ۸۵۱ می‌گرداند.
- [ ] روش «نزدیک‌ترین ۱۰۰۰» قیمت ۸۵۰٬۵۰۰ را به ۸۵۱٬۰۰۰ گرد می‌کند.
- [ ] گام دلخواه ۵۰۰۰ درست اعمال می‌شود.
- [ ] گرد کردن هیچ‌وقت قیمت نهایی را بزرگ‌تر یا مساوی قیمت اصلی نمی‌کند.

## ۴) زمان‌بندی

- [ ] تخفیف بدون تاریخ، بلافاصله فعال می‌شود.
- [ ] تاریخ شروع در آینده: قیمت فعلی تغییر نمی‌کند و در زمان شروع فعال می‌شود.
- [ ] تاریخ پایان در آینده: در زمان پایان قیمت حراج پاک می‌شود.
- [ ] تاریخ پایان قبل از شروع رد می‌شود.
- [ ] تاریخ نامعتبر (مثلاً ۲۰۲۶-۱۳-۴۵) رد می‌شود.
- [ ] فیلدهای تاریخ با **تقویم شمسی** باز می‌شوند و پیمایش ماه/سال کار می‌کند.
- [ ] زمان انتخاب‌شده در پنل شمسی است، اما در `_sale_price_dates_from/_to`
      تاریخ میلادی ذخیره می‌شود.
- [ ] چیدمان تب «تخفیف ویرامون» درست است: برچسب و گزینه در یک ردیف‌اند و توضیح
      زیر همان گزینه قرار می‌گیرد.
- [ ] در عرض کم (زیر ۷۸۲ پیکسل) برچسب تمام‌عرض می‌شود و توضیح بدون تورفتگی زیر آن می‌آید.
- [ ] اگر تخفیف زمان‌بندی شده باشد، بالای تب پیام «زمان‌بندی شده» با تاریخ شمسی دیده می‌شود.
- [ ] اگر تاریخ پایان گذشته باشد، پیام قرمز «تاریخ پایان گذشته است» دیده می‌شود.
- [ ] بعد از پاک کردن دستی `_sale_price` در دیتابیس، با باز کردن ویرایش محصول قیمت حراج دوباره ساخته می‌شود.
- [ ] تاریخ‌ها با منطقه زمانی وردپرس ذخیره می‌شوند (تغییر timezone رفتار را عوض نکند).
- [ ] در «ووکامرس ← وضعیت ← زمان‌بندی‌شده» اکشن‌های `viramoon_pd_discount_start/end` دیده می‌شوند.

## ۵) تعارض با حراج دستی

- [ ] محصولی با قیمت حراج دستی ۷۰۰٬۰۰۰ بسازید و تخفیف ویرامون بگذارید.
- [ ] ذخیره بدون تیک «بازنویسی» رد می‌شود و پیام واضح نمایش داده می‌شود.
- [ ] با تیک بازنویسی، تخفیف اعمال می‌شود.
- [ ] پس از پایان/لغو تخفیف، قیمت ۷۰۰٬۰۰۰ بازگردانده می‌شود.
- [ ] اگر بین این دو، مدیر قیمت حراج را دستی عوض کند، افزونه آن را پاک نمی‌کند.

## ۶) Variation تکی

- [ ] هر Variation فیلدهای مستقل دارد.
- [ ] تخفیف هر Variation از قیمت اصلی همان Variation محاسبه می‌شود.
- [ ] Variation بدون قیمت اصلی پیام «قیمت اصلی ندارد» می‌دهد و تخفیف نمی‌گیرد.
- [ ] زمان‌بندی هر Variation مستقل است.
- [ ] قیمت نمایشی محصول متغیر (حداقل/حداکثر) پس از ذخیره به‌روز می‌شود.

## ۷) اعمال گروهی Variationها

- [ ] دامنه «همه» همه Variationها را هدف می‌گیرد.
- [ ] دامنه «انتخاب‌شده» فقط موارد تیک‌خورده را هدف می‌گیرد.
- [ ] دامنه «بدون تخفیف فعال» موارد دارای تخفیف را رد می‌کند.
- [ ] پیش‌نمایش تعداد و قیمت قبل/بعد را نشان می‌دهد.
- [ ] دکمه «اعمال» قبل از پیش‌نمایش غیرفعال است.
- [ ] اعمال بدون تأیید (confirm) انجام نمی‌شود.
- [ ] Variation بدون قیمت/غیرفعال در گزارش «ردشده» با دلیل می‌آید.
- [ ] نوار پیشرفت تا ۱۰۰٪ پیش می‌رود.
- [ ] «لغو تخفیف گروهی» قیمت حراج را پاک می‌کند.
- [ ] اجرای دوباره اعمال، تخفیف مرکب ایجاد نمی‌کند (قیمت ثابت می‌ماند).

## ۸) تخفیف گروهی محصولات

- [ ] فیلتر نوع محصول، دسته‌بندی، جست‌وجو و شناسه دستی کار می‌کند.
- [ ] صفحه‌بندی محصولات درست است.
- [ ] انتخاب چند صفحه‌ای حفظ می‌شود.
- [ ] پیش‌نمایش قبل از اعمال اجباری است.
- [ ] محصول متغیر با گزینه «همه متغیرها» روی همه Variationها اعمال می‌شود.
- [ ] گزینه «فقط واجد شرایط» موارد بدون قیمت را رد می‌کند.
- [ ] گزارش نهایی تعداد به‌روزرسانی/ردشده را نشان می‌دهد.

## ۹) کارمزد درگاه

- [ ] در تنظیمات، درصد ۱۵ برای درگاه تست ثبت می‌شود.
- [ ] با روش «کاهش تخفیف» و تخفیف ۲۰٪، در تسویه‌حساب قیمت ۹۵٪ قیمت اصلی می‌شود.
- [ ] با روش «افزایش قیمت»، قیمت = قیمت تخفیف‌خورده ÷ ۰٫۸۵.
- [ ] با روش «ردیف کارمزد»، یک ردیف fee جداگانه در سبد اضافه می‌شود.
- [ ] با تغییر درگاه، جمع‌ها به‌صورت خودکار بازمحاسبه می‌شوند.
- [ ] با درگاه بدون کارمزد، هیچ تغییری اعمال نمی‌شود.
- [ ] قیمت صفحه محصول/دسته‌بندی تغییر نمی‌کند (فقط سبد/تسویه).
- [ ] محاسبه دوباره سبد (رفرش صفحه) تخفیف مرکب ایجاد نمی‌کند.
- [ ] با فعال بودن «محصولات بدون تخفیف»، محصول بدون تخفیف هم کارمزد می‌گیرد.

## ۱۰) امنیت

- [ ] درخواست AJAX بدون nonce رد می‌شود.
- [ ] کاربر بدون `edit_products` نمی‌تواند AJAX را اجرا کند.
- [ ] ذخیره محصول بدون nonce تغییری ایجاد نمی‌کند.
- [ ] مقدار غیرعددی/تاریخ نامعتبر در AJAX با پیام خطا رد می‌شود.
- [ ] شناسه محصول/متغیر نامعتبر باعث خطای PHP نمی‌شود.

## ۱۱) داده و حذف

- [ ] غیرفعال‌سازی افزونه هیچ قیمتی را تغییر نمی‌دهد.
- [ ] با سیاست «نگهداری»، حذف افزونه داده‌ها را نگه می‌دارد.
- [ ] با سیاست «حذف»، متادیتای افزونه پاک و حراج ما برداشته می‌شود.
- [ ] قیمت‌های عادی محصول پس از حذف دست‌نخورده‌اند.

## ۱۲) سازگاری نمایشی

- [ ] صفحه ویرایش محصول در عرض موبایل قابل استفاده است.
- [ ] CSS/JS فقط در صفحات محصول و تخفیف گروهی بارگذاری می‌شوند.
- [ ] با یک قالب محبوب (Storefront) بدون خطای کنسول کار می‌کند.
- [ ] با کش صفحه فعال، پس از ذخیره قیمت جدید دیده می‌شود.
